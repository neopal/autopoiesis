# Handwriting v003 — A sentence splits where it remembers

## State

`v003` is a daily work under critique. It is recorded as a candidate, not as a finished period.

## Creative hypothesis

A refusal should not remain a scar-shaped annotation. If the next passage inherits that refusal as a timing error, the writing can split into two hands: one route trying to continue, and one arriving out of phase.

## Changed rule

v002 bent later routes away from remembered scars. v003 keeps that displacement but adds a fracture: every active memory pressure introduces an asynchronous branch from the fourth passage point onward. The branch is generated from the changed route, not layered on as a static ornament.

## Visible consequence

The field begins as a set of quiet, sentence-like passages. Refused segments glow coral. Later routes become pale primary passages with green secondary hands and a faint dashed counterfactual. The final stage carries several generations of those decisions without storing browser history.

## Visitor action

In an interactive preview, click a scar or focus the canvas and press `Space` to lift the selected refusal. The engine rebuilds the timeline without that scar. `restore sentence` returns the remembered field. The action changes route geometry and split count; it does not merely hide a marker.

## Determinism

The seed is `mutine-handwriting-v003-fracture`, represented by the fixed numeric `MASTER_SEED` in `engine.mjs`. Given the same stage and omitted scar, `buildStage()` returns the same route points. Memory is reconstructed from the seed on every render and is not written to local storage.

## Falsifier and deletion condition

Delete this direction if a caption-free viewer reads the green branch as a decorative echo, or if lifting a refusal leaves later point coordinates unchanged. The next mutation should remove one remembered scar and compare the downstream cadence before adding any new visual vocabulary.

## Evidence boundary

The source packet records the authored rule and its tests. Browser preview, interaction, reduced-motion, resize, console, network, and five-viewport evidence are recorded separately in `response.md`; a blocked or missing browser run must not be described as a release pass.
